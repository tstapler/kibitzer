# kibitzer

Advisory, diff-aware code/doc quality checks for AI agents, CI, and local dev.

## Default check catalog

`config::default_checks()` (`src/config.rs`) runs everywhere by default,
pylint-style — no `.claude/inspect.json` required. This is the standard: a
new native per-file checker that doesn't need repo-specific setup (an
architecture model, a `command` a project must supply) goes in
`default_checks()` as part of landing it, not as a follow-up someone has to
remember. `comment-quality-<lang>` (`docs/comment-quality.md`) is wired in
this way, alongside `syntax-rules-<lang>` (`docs/syntax-rules.md`),
`markdown-link-integrity`, `primitive-obsession`, `duplicate-code`,
`duplicate-code-cross-file`, and the Go-specific
`go-blank-imports`/`go-ignored-error`/`go-error-context`. A local
`.claude/inspect.json` overlays the defaults rather than replacing them —
see `docs/suppressing-checks.md` for how a repo disables or scopes one.
A separately installed checker (`kibitzer plugin install|list|remove|status`)
is chained in alongside these defaults the same way — see `docs/plugins.md`.
`testdata/comment-quality-corpus/` holds a hand-labeled how/why/ambiguous
comment corpus for training/testing/tuning a future comment-quality
classifier — see its README for provenance and known limitations.

## Writing a new check

Before landing a new native checker (or a meaningful change to an existing one's
rules/thresholds), backtest it, not just unit-test it — a check that only ever ran
against its own test fixtures hasn't been checked for real-world noise. Two
complementary tools, both required, not either/or:

- `kibitzer check backtest <name>` (`docs/backtesting.md`) replays real historical
  edits from Claude Code session transcripts (`~/.claude/projects/*/*.jsonl`) — answers
  "does it fire on the edits it's meant to catch, and how often does it fire on ones it
  shouldn't."
- The real-world repo corpus (`docs/backtest-repos.md`): a fixed set of large,
  well-regarded public codebases (`kubernetes/kubernetes`, `apache/cassandra`,
  `servo/servo`, `BurntSushi/ripgrep`, `denoland/deno`, `microsoft/vscode`) plus
  `stapler-squad`, cloned via `scripts/clone-backtest-repos.sh`. Run the new checker
  against the whole tree (`kibitzer run <repo>` or `kibitzer check native <name> <file>`
  piped from `find`) to see how it behaves at a scale and style diversity no hand-built
  fixture set can approximate. Use `scripts/backtest-triage.py`
  (`docs/backtest-triage/README.md`) to track true/false-positive triage across repeated
  runs instead of re-reading raw output every time.

A checker that hasn't been run against this corpus at least once isn't done — see
`docs/check-ideas.md` for the "confirmed transcript occurrence" bar new check ideas are
already held to; the public-code corpus is the same discipline applied on the output
side (does it fire cleanly at scale) rather than the input side (is there evidence this
problem happens).

## Cutting a release

Release automation is `cargo-dist` (`.github/workflows/release.yml`, autogenerated —
don't hand-edit it; regenerate with `dist init` / `dist generate` if it needs to change).
It triggers only on a pushed version tag, not on merge to `master`.

1. Merge the feature/fix PR to `master` first. Releases bundle whatever's on `master`
   at tag time — don't tag mid-PR.
2. Bump the version in `Cargo.toml` (`[package].version`), then run `cargo build` so
   `Cargo.lock`'s matching entry updates too. Commit both files together, push to `master`.
3. Tag and push: `git tag vX.Y.Z && git push origin vX.Y.Z`. This is what fires the
   `Release` workflow — a commit alone does nothing.
4. Watch it: `gh run list --workflow=release.yml --limit 1`, then
   `gh run view <id> --json status,conclusion,jobs`. Expect `plan`,
   `build-local-artifacts` (per target), `build-global-artifacts`, `host`,
   `publish-homebrew-formula`, `announce` — all `success`. On a plain PR push (no tag),
   only `plan`/`test` run and the rest correctly show `skipped`; don't mistake that for
   a broken pipeline.
5. Confirm the Homebrew tap actually updated — CI reporting `success` isn't proof by
   itself: `gh api repos/tstapler/homebrew-tap/contents/Formula/kibitzer.rb --jq '.content' | base64 -d | grep version`.
6. Upgrade your local install for real, don't hand-patch the Cellar binary:
   `brew upgrade kibitzer` (add `HOMEBREW_NO_AUTO_UPDATE=1` if `brew update`'s full
   index refresh is slow and you just need this one formula). Verify with
   `brew list --versions kibitzer` and `kibitzer --help`.

No changelog file is maintained yet — the GitHub Release body is auto-generated by
cargo-dist from commit history since the last tag.
