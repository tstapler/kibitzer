# Bash checkers: corpus false-positive triage (2026-10-18)

Corpus: 150 shell scripts (all `*.sh`) from `tstapler/dotfiles`, `tstapler/stapler-squad`,
`tstapler/zerobrew`, `gitlabhq/gitlabhq`, `microsoft/vscode-docs`, `gohugoio/hugo`,
`apache/cassandra` (the list was machine-local; 74 of the 150 were under `~/code/github.com`,
the rest in dotfiles). Binary: `target/debug/kibitzer` at `094bbdf`. Every finding's cited line
was opened and judged by hand; per-finding records are in the per-repo shards
(`docs/backtest-triage/<repo-slug>/<rule>.jsonl`, written with `scripts/backtest-triage.py mark`).

Records are keyed `(file, line, rule)`, so 4 findings that share a key with another finding
(`nil_safety_check.sh:34` x3 same verdict, `nil_safety_check.sh:55` x2 same verdict,
`migrate-to-pnpm.sh:103` x2 mixed) are one record each with the note covering both. Counts below
are per finding (116), records are 112.

## ADR-001 <40% FP bar

Strict reading (debatable excluded), which is the only reading that is not hand-waving:

- `replace-magic-literal`: not met (52.5%).
- `long-function`: met (0%).
- `syntax-rules-bash` as a whole: met (36.5%), but only because `long-function` dilutes `replace-magic-literal`.
- `commented-out-code`, `over-commented`: not met (100%, n=7 and n=2). `verbose-comment` met (n=1, meaningless).
- `comment-quality-bash` as a whole: not met (90%).
- `duplicate-code`: no data.
- Overall: not met strictly (42.1%); met only if every debatable finding is counted as a TP (34.5%).

## FP classes

1. **`>&2` / `2>&1` read as numeric literal 2** (18 findings, 23% of all `replace-magic-literal`
   output; also `exit 2`, `-mindepth 2`, `$2`). Without this class, `replace-magic-literal`
   would be 13 FP / 28 TP / 18 debatable = 31.7% strict.
2. **Shell boolean/display strings flagged as magic strings** (13 findings): `"true"`/`"false"`/
   `"yes"`/`"no"` env flags, `"{}"`, `printf "\n"`, `"done!"`, `"    OK"`, `"===="`, `"^$"`.
3. **Prose and usage-example comments read as code** (all 7 `commented-out-code` findings and
   both `over-commented`): `#   ./script.sh -n 5 ...` usage lines, `# auth_value=2 -> ...` value docs,
   `#author=...` header metadata, an env-var name in a sentence, and a reference list above an
   unrelated function.

## Debatable buckets

- OS/arch names (`"linux"`, `"darwin"`, `"x64"`, `"arm64"`, ...) repeated in platform branches (9).
- Repeated unsupported-OS / log-hint messages (4); theme palette values in `powerlevel9k.sh` (2).
- Three `long-function` hits: a 119-line heredoc config emitter and two flat `case` dispatches
  (41 and 51 lines).
- `radius*2` ffmpeg arithmetic and a repeated 5-second timeout (2 numeric).

## Caveats

- `tstapler/dotfiles` and `tstapler/stapler-squad` are live clones; permalinks pin to HEAD at triage
  time (`cf9bd68`, `d320c038c`) and files with uncommitted edits may not match line-for-line.
- 76 of the 150 files are the author's own dotfiles and 30 are gitlabhq CI helpers; only 5 are
  hugo, 2 cassandra, 8 vscode-docs. Rates reflect that skew.
- Existing shards in `tstapler-stapler-squad` and `apache-cassandra` for these rule ids hold Go
  triage; the bash records were appended, no existing record was changed (`git diff --numstat`: 0 deletions).

## Re-measurement after the FP fixes

The rules were then changed to remove the top three false-positive classes above: `replace-magic-literal` now exempts redirect targets and plain command-argument numbers (`>&2`, `exit 2`, `sleep 5`), shell boolean/separator/escape strings and `echo`/`printf` arguments (`bash_is_exempt_literal`, `src/checkers/rules.rs`); `comment-quality-bash` no longer runs `commented-out-code` or `over-commented` (`BASH_SKIPS_CODE_HEURISTICS`, `src/checkers/comment_quality.rs`), so only `verbose-comment` runs for shell.

Same 150-script sample, same three commands, joined to the per-finding verdicts by (file, line, rule):

| | Before | After |
|---|---|---|
| Findings | 116 | 72 |
| True positive | 55 | 52 |
| False positive | 40 | 0 |
| Debatable | 21 | 20 |

- Of the 72, 70 matched an existing verdict; the other 2 are `numeric literal 2` findings in arithmetic (`CHROME_H / 2`, `2 ** i` backoff) whose anchor line moved when other occurrences were exempted. I judged both debatable.
- Strict FP rate on this sample: 0 of 52 TP+FP (0%); debatable counted as FP: 20 of 72 (27.8%). Both are under the 40% bar.
- Cost: 3 findings previously judged true positive and 1 judged debatable are no longer reported.
- **Caveat:** this re-scores the same sample the exemptions were tuned against, so 0% is a ceiling on what the sample can show, not an independent estimate. A fresh sample (different repos) has not been run. `duplicate-code` produced no findings on this sample, so it remains untested at scale.

## Fresh-sample check (kubernetes first 150, untuned)

An independent estimate on files the rules were never tuned against. Nothing in `src/` was changed and `scripts/backtest-triage.py mark` was not used; verdicts live only in this section.

- **Sample:** first 150 of `find ~/code/github.com/kubernetes/kubernetes -name '*.sh' -not -path '*/vendor/*' -not -path '*/_output/*' | sort`. Binary: `target/release/kibitzer` (built after the last `src/` edit). Commands: `check native syntax-rules-bash`, `comment-quality-bash`, `duplicate-code` per file. Raw output: `/home/tstapler/.cache/ssq-e2e-tmp/k8s-fresh.out`.
- **Draw:** `random.seed(20261019)`; 70 of the 277 findings, allocated proportionally per rule (largest remainder), then `random.sample` within each rule.
- **Classification rubric:** true_positive = the finding is accurate and a reviewer could act on it. false_positive = the finding is wrong about the code. debatable = accurate but a threshold-edge, declarative-data or low-value hit (e.g. a 41-48 line flat `long-function`, a heredoc emitter, a repeated literal in a table of arguments).

### Top false-positive classes

1. **Quote mis-pairing in `replace-magic-literal` (all 5 FPs).** The checker reports the text *between* two quoted strings as a literal when a double-quoted string is followed by a line continuation or more arguments, e.g. `"${PROJECT}" \` newline `--zone "${ZONE}"` yields the "literal" `" \<newline>        --zone "`, and `"${name}" --project "${PROJECT}"` yields `" --project "` (reported 20 times in `cluster/gce/util.sh`). Sampled FPs, all in `cluster/gce/util.sh`: lines 3130, 3400, 3401, 3783 and 4034. Heuristic extent on the whole population: 17 of the 134 magic-literal findings begin with `" ` (closing quote then space) and 13 more have a multi-line literal, so roughly 13-22% of that rule's output is likely this bug. This is a real defect, not a threshold question.
2. Not false positives but the bulk of the debatable bucket (24): repeated command/flag-style arguments (`"10"` retry counts, `"calico-policy-controller"`, `"${KUBE_ROOT}/cluster/kube-down.sh"`), repeated `sed` substitution lines across sibling functions, declarative case-arm region lists, and iptables rule tables.
3. `long-function` hits at 41-48 lines whose length comes from backslash-continued command lines (`codegen::informers`, `codegen::clients`, `codegen::defaults`) or a heredoc config emitter (`setup-containerd`, 118 lines).
4. `duplicate-code` on a YAML heredoc fixture (`kube-addons-test.sh:204`): test data, not logic.

### Does the <40% bar hold?

- **Strict FP rate: yes.** 10.9% (5/46) is under 40%, and every FP traces to one defect (quote mis-pairing).
- **Debatable counted as FP: no.** 41.4% (29/70) is over 40%, by a single finding. Per rule, `replace-magic-literal` is 50.0% and `long-function` 39.3%.
- The earlier 0% strict / 27.8% figures were measured on the tuning sample and overstated generality: on untuned files the strict rate is about 11% and the debatable-inclusive rate about 41%.
- The quote mis-pairing defect was not present in, or not surfaced by, the tuning sample and is the one item to fix before relying on `replace-magic-literal` output. Threshold-edge `long-function` and low-value repeated-literal hits are the other half of the gap.
- Limits: one repository (Kubernetes, GCE/build/hack scripts), first-150 by path sort (skewed toward `build/`, `cluster/`, `hack/`), single reviewer, verdicts are judgment calls (the debatable bucket in particular is rubric-dependent).

### Follow-up fix for the fresh-sample false positives

The 5 fresh-sample FPs (`" --zone "`, `" --project "`) were not a rule bug: the same command parses correctly in isolation, but `cluster/gce/util.sh` has a tree-sitter-bash parse error earlier in the file that desynchronises quote pairing. `bash_tree_has_error` (`src/checkers/rules.rs`) now makes `replace-magic-literal` report nothing in a file whose tree has an error. Parse errors affected 21 of 300 sampled scripts (7%: the 150 tuning-sample scripts plus the first 150 kubernetes scripts).

Measured effect (same kubernetes 150 files, debug binary, `syntax-rules-bash` only): `replace-magic-literal` findings 134 -> 66; `util.sh` 41 -> 0. The sampled 70 were not re-drawn, so the new strict FP rate is not re-estimated; all 5 sampled FPs were in `util.sh` and are gone. Cost: true and debatable findings inside parse-error files are no longer reported either, and that loss was not quantified.
