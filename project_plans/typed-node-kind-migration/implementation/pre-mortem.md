# Pre-mortem: typed-node-kind-migration
**Date**: 2026-09-22

## Failure Modes

| # | Failure | First Symptom | Prevention | Severity |
|---|---------|--------------|------------|----------|
| 1 | Pre-migration backtest baselines (Task N.N.Na, "save to `/tmp/*-baseline.txt`") are captured by independent worker sessions across ~17 stories; `/tmp` isn't durable or shared across sessions/sandboxes, so by Phase 4 (Task 4.1.1d, "diff against each checker's original pre-migration baseline") most of those files no longer exist. | Task 4.1.1d can't locate earlier stories' baseline files; the story proceeds anyway using only the current pre-Phase-4 output as a stand-in "baseline," silently losing the cross-story integration check the story exists to perform. | Add an AC to every baseline-capture task requiring the baseline output to be pasted into that story's PR/commit description (durable, git-tracked) in addition to `/tmp`, and add an explicit AC to Story 4.1.1 that Task 4.1.1d **fails closed** (blocks completion) if any prior story's baseline can't be retrieved, rather than substituting a fresh capture. | P1 |
| 2 | Under time pressure, a worker whose sandbox lacks the cloned `docs/backtest-repos.md` corpus (or hits a `kibitzer` CLI mismatch) gets a degenerate/empty backtest result and reports "0 findings pre- and post-migration — identical" as proof of no regression, when it's actually proof the check never ran. | Backtest logs show 0 findings in both runs for a checker expected to fire reliably on the corpus (e.g. `go-error-context` against `kubernetes/kubernetes`), and no reviewer questions the zero. | Add a sanity-check step to every backtest task: the pre-migration baseline must contain a nonzero finding count, or the task must record an explicit, checked reason it's legitimately zero (e.g. checker genuinely doesn't fire on the sampled corpus slice) before it's accepted as a valid baseline. | P1 |
| 3 | A later, unrelated PR/session (including kibitzer's own dogfooded checks, e.g. `primitive-obsession` or a future manual cleanup pass) "fixes" one of the 11 seam sites in `rules.rs`/`symbol_extract.rs`, because the `// SEAM(typed-node-kind-migration): ...` banner sits once above the function signature rather than on the specific line being touched, so a scoped diff or single-line edit doesn't surface it. | A future PR's diff shows `cfg.if_kind`/`callee_text_for`'s match arm converted to a typed enum with no reference to ADR-001; CI passes (it compiles) but silently changes cross-grammar behavior or reintroduces the "same-spelled kind, different enum type" bug ADR-001 exists to prevent. | Add a mechanical CI/completeness check (extending the Phase 4 sweep into a permanent one — see #4) that fails if the exact seam-marked lines in `rules.rs`/`symbol_extract.rs` (a pinned line/function list) are edited without the seam-comment count for that file also changing; alternatively require the banner on each seamed line, not once per function, so it's visible in any single-line diff. | P2 |
| 4 | The migration converts existing call sites but adds no forward-looking guardrail (lint, native kibitzer check, or CI grep) forbidding **new** raw `.kind() == "literal"` comparisons in the 23 migrated files — so a future contributor or agent adds a new checker function right next to a converted one using a raw string, silently recreating the exact typo-risk class this migration exists to close. | Nothing at merge time — it passes all CI gates cleanly. Only surfaces later when a typo in the new raw comparison causes a silent false-negative in production or a backtest run, the same failure class requirements.md names as the whole reason for this migration. | Add a Phase 5 (or fold into 4.1.1) story that lands the completeness-sweep regex (`rg -n '\.kind\(\)\s*(==|!=)|...'`) as a permanent CI gate scoped to the 23 in-scope files, failing any future PR that introduces an unexplained hit (one not immediately adjacent to a documented seam/non-goal comment) — turning the one-time sweep into standing enforcement instead of a point-in-time check. | P1 |
| 5 | Removing `node_kind.rs`'s blanket `#![allow(dead_code, unused_imports)]` (Story 4.1.1) reveals that most variants across the 8 generated enums are genuinely unused — since only ~140 of many hundreds of possible node kinds were ever compared against — producing far more `-D warnings`-gated failures than the story's AC anticipated ("a scoped allow on just that item"), and the story either blocks the whole migration's merge on unrelated cleanup, or quietly re-adds a blanket allow, defeating the completion signal's purpose. | Task 4.1.1a's `cargo build --workspace` emits dozens-to-hundreds of `dead_code`/`unused_imports` warnings spread across all 8 enums, not the "obscure single variant" case the AC's example describes. | Before finalizing Story 4.1.1's AC, run a throwaway dry-run (remove the allow, `cargo build --workspace`, count warnings) as a Phase-3-exit spike, and size the story's acceptance bar off the real count — e.g. explicitly permit a single per-enum `#[allow(dead_code)]` (rather than per-variant) as an acceptable outcome if the real count is large, so the story doesn't stall the merge on a cleanup scope no one budgeted for. | P2 |

## P1 Items (address before implementation)
- [ ] #1 — Add a "paste baseline into PR/commit description" AC to every baseline-capture task, and change Task 4.1.1d's AC to fail-closed if any prior story's baseline is unavailable.
- [ ] #2 — Add a "baseline must be nonzero or explicitly justified as zero" sanity-check AC to every backtest task in Phases 1–4.
- [ ] #4 — Add a Phase 5 (or extend 4.1.1) story that turns the migration-completeness sweep into a permanent CI gate on the 23 in-scope files, not a one-time Phase 4 check.
