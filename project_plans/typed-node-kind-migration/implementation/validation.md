# Validation Plan: typed-node-kind-migration

**Date**: 2026-09-22

## Happy Path Scenario
Given a checker file with N raw `.kind()` string comparisons against named concrete kinds, when the comparisons are converted to `<Lang>Kind::of(node) == <Lang>Kind::Variant`, then `cargo build --workspace` succeeds, `cargo test --workspace` passes unchanged, and the checker's backtest-corpus finding counts (transcript + real-world corpus) are byte-identical to the pre-migration baseline.

## Test Stack

- **Unit/Integration**: `cargo test --workspace` (existing suite, unchanged) — the baseline correctness check present in every story's AC. No new `#[test]` functions are needed for the enum-conversion logic itself, since the conversion is a type-level, not behavior-level, change and the existing test suite already exercises the compared code paths.

- **Compile-time safety** (the one genuinely new test class this migration should add): **Recommendation: a documented one-time manual verification, performed once during Story 1.1.2, not repeated per file.** A deliberate compile failure cannot be asserted inside `cargo test` itself — `cargo test` only runs after a successful `cargo build`, so a real "does this typo fail the build" check requires *invoking a build that is expected to fail*, which is fundamentally a manual/scripted-outside-cargo-test step, not a `#[test] fn` (a `trybuild`-style compile-fail harness would be new test infrastructure, which is out of scope per requirements.md's "no new codegen/enum-generation mechanism" and adds a dependency for a fact `<Lang>Kind`'s enum-typing already guarantees by construction — every migrated call site is *structurally* incapable of accepting a nonexistent variant name, so the protection doesn't need re-demonstrating 22 more times). Concretely, Story 1.1.2's Task 1.1.2 sequence performs this once:
  1. Migrate `go_ignored_error.rs`'s 4 comparisons.
  2. Temporarily edit one converted line to reference `GoKind::SelectorExpresion` (typo).
  3. Run `cargo build --workspace`, capture and record the compiler's "no variant named `SelectorExpresion`" error text in the story's commit/PR description (a one-line note, not a new doc file).
  4. Revert the typo.
  This is recorded as evidence in Story 1.1.2's PR description, not as a repeatable `#[test]` — repeating it in all 17 stories would test the Rust compiler's own enum exhaustiveness checking, not this migration's code.

- **Behavior-unchanged verification**: kibitzer's own backtest mechanism (`kibitzer check backtest <name>`, `kibitzer check native <name> <file>`), mandated per-story in plan.md. "Pass" means precisely: (1) the finding **count** is identical, AND (2) the **file:line list** of every finding is identical (byte-identical set comparison, not just a count match — two different findings could coincidentally sum to the same count), matching Story 1.1.2's own AC pattern (`"the finding count and file:line list are byte-identical"`). Workflow per story:
  1. Before editing, run `kibitzer check native <name> <file(s)>` (and `kibitzer check backtest <name>` where a transcript corpus exists) and save output to `/tmp/<name>-baseline.txt`.
  2. After editing, re-run the identical command and `diff` against the saved baseline.
  3. Per the plan's backtest-regression merge gate: any non-empty diff blocks merge for that story — it is never advisory.
  - **Stories needing a different (wider) scope than a naive per-file reading of plan.md might suggest**: 3.1.1 and 3.2.1 are explicitly **multi-checker, shared-infra backtests** (every checker backed by `rules.rs`/`symbol_extract.rs`, not just one named checker) — confirm the exact consumer list via `kibitzer list_checks` and `grep -rl rules::\|symbol_extract:: src/checkers/` *before* capturing baselines, since guessing the list risks silently under-scoping the regression check for the two highest-risk files in the migration. 3.3.1 and 3.3.2 similarly require multi-language corpus coverage (Go+Java+Kotlin+Python) rather than a single language, because each function inside those files is single-grammar but the file as a whole fans out to every grammar. 3.1.2 and 3.2.2 are the inverse case — deliberately **narrower** than a full backtest, since they are comment-only diffs (a spot-check suffices, confirmed via `git diff` showing no logic lines changed). 4.1.1 is explicitly the **widest** scope: every checker's finding count is compared against its *original* pre-migration baseline (captured at that checker's own story), not against the immediately-preceding story's baseline, to catch a cross-file interaction no single story's backtest could see.

- **Seam-format check** (`rules.rs`'s 8 + `symbol_extract.rs`'s 3 = 11 documented sites): a literal grep-based script, not a `#[test] fn` — decision rationale: the seam comment is a source-text marker for human/tooling greppability (explicitly so Phase 4's completeness sweep can distinguish "intentionally seamed" from "missed," per plan.md's own Seam glossary entry), not a runtime invariant a compiled test can check, and a `#[test]` would need to parse Rust source as text anyway (via `syn` or regex), which is no safer than a standalone script and adds a test-time dependency for a one-time-per-story check. Concrete script, run once per seam story (3.1.2, 3.2.2) and once more as part of 4.1.1's completeness sweep:
  ```sh
  # scripts/check-seam-comments.sh (ad hoc, not necessarily committed — may be run inline)
  rg -n '// SEAM\(typed-node-kind-migration\): .+ — see ADR-001\.' \
     src/checkers/rules.rs src/symbol_extract.rs
  ```
  Pass criterion: exactly 8 matches in `rules.rs` (6 engine functions + `collect_identifiers`'s L899 site + the `rules.rs:784` substring-check site) and exactly 3 matches in `symbol_extract.rs` (`enclosing_kind_name`, `walk_calls`'s `function_kinds.contains`, `callee_text_for`) — 11 total, matching plan.md's Seam glossary entry's stated count. A count that doesn't match 8/3 means a seam site is missing its banner or a banner was miscopied (e.g. wrong crate name in the parenthetical, missing the `— see ADR-001.` suffix) and must be fixed before the story is marked done.

- **Migration-completeness sweep** (Story 4.1.1, exact command per plan.md, elevated here to a precise executable step):
  ```sh
  rg -n '\.kind\(\)\s*(==|!=)|\.kind\(\)\.contains\(|match\s+\S+\.kind\(\)' src/ \
    > /tmp/completeness-sweep-raw.txt
  ```
  Triage procedure: every line in the output must be one of:
  1. **A false-positive scope file hit** (`src/dedup.rs`, `src/plugin.rs`) — confirmed `std::io::Error::kind()`, excluded by inspection (Story 1.1.1).
  2. **`src/node_kind.rs` itself** — excluded per requirements.md (generated code, not a migration target).
  3. **Immediately adjacent to a `// SEAM(typed-node-kind-migration): ...` banner** — cross-check against the 11-line seam-format-check output above.
  4. **Immediately adjacent to a documented non-goal comment** citing the anonymous-token/non-goal reasoning from the Tech Debt Disposition table (`complexity.rs`'s `&&`/`||` arm and its 2 `function_kinds.contains` seam-exclusion sites, `declarations.rs`'s Kotlin class/interface scan and its 3 test-assertion siblings, `import_graph.rs`'s Kotlin `"*"` and Java `"static"` sites, `symbol_extract.rs`'s 3 non-goal `find_child_by_kind` sites).
  Any line not matching one of these 4 buckets is an unexplained hit — a missed migration site — and must be converted (if mechanical) or seam/non-goal-annotated (if genuinely cross-grammar or anonymous-token) before Story 4.1.1 is marked done. Re-run the sweep after any fix; pass criterion is zero unexplained hits.

- **Idiom-consistency skim** (Story 4.1.1, exact command per plan.md):
  ```sh
  rg 'Kind::of\(' -A1 src/ > /tmp/idiom-skim.txt
  ```
  Manual read-through (not scriptable as a pass/fail, since "consistent style" is a judgment call clippy's `match_like_matches_macro` lint doesn't fully cover): confirm every hit is either `<Lang>Kind::of(node) == <Lang>Kind::Variant` or `matches!(<Lang>Kind::of(node), <Lang>Kind::A | <Lang>Kind::B)` form. Flag (and fix) any hit using `from_kind_str` where a live `Node` was available, or a hand-written `match` expression that should have collapsed to `matches!` per the plan's Pattern Decisions table.

- **New test function naming** (matching this repo's existing style — spot-checked against `src/checkers/go_ignored_error.rs`'s `flags_discarded_last_value`, `does_not_flag_comma_ok_type_assertion`, `still_flags_when_the_import_is_not_under_this_module`): this migration adds no new `#[test] fn`s to the checker files themselves (behavior is unchanged by definition, so no new checker-behavior test cases are warranted). The one net-new piece of test-shaped work is the seam-format check, which is a script rather than a `#[test]`. If a future maintainer wants it as an actual `#[test]` (e.g. inside `rules.rs`'s own test module, parsing its own source file), the descriptively-named form consistent with house style would be:
  - `fn all_seam_comments_present_and_correctly_formatted()`
  - `fn zero_unexplained_kind_comparisons_remain_after_migration()` (for a hypothetical committed version of the completeness sweep)
  These are named here for completeness but the recommendation is to keep both as ad hoc `rg`-based scripts run manually during Stories 3.1.2/3.2.2/4.1.1, not committed `#[test]` functions, since they check source-text conventions rather than runtime behavior and would otherwise need to re-parse the crate's own source from within the test binary for no additional safety benefit.

## Coverage Targets and How to Measure

This migration's "coverage" is not a line-coverage percentage — it is **23/23 in-scope files migrated, or explicitly seam/non-goal-documented**, since the entire point is closing every named-kind comparison's typo risk, not exercising a percentage of lines. Measure directly:

```sh
# Files with at least one remaining raw .kind() comparison after the migration:
rg -l '\.kind\(\)\s*(==|!=)|\.kind\(\)\.contains\(|match\s+\S+\.kind\(\)' src/
```
Cross-reference this file list against the 23-file scope list in requirements.md: every file must appear in the Phase 4 completeness sweep's "explained" bucket (seam comment, non-goal comment, or false-positive-scope-file/generated-code exclusion) — there is no numeric threshold below 100%, since an unexplained partial conversion is exactly the invisible-typo failure mode this migration exists to eliminate.

`cargo tarpaulin` is not recommended here as more than an optional sanity check: this migration doesn't add new branches that need exercising (the `<Lang>Kind::of()` calls run through code paths the existing test suite already covers), so a tarpaulin percentage would measure the pre-existing checker test suite's coverage, not this migration's completeness. If run at all, use it only to confirm no migrated line became provably dead code (i.e., cross-check its output against the Phase 4 `#![allow(dead_code)]` narrowing in Story 4.1.1), not as a merge gate.
