## Concerns
- [ ] **Optional Task 1.1.3a's status isn't consistently threaded through the plan.** `requirements.md` AC#7 and `.backlog-context.md` AC#6 both mark the `CATALOG.description` edit "(Optional)", but the Dependency Visualization diagram treats Task 1.1.3a as a normal pipeline step ("independent, can run anytime... before 1.2.1a"), and Story 1.2.1's own Given clause for the final verification gate presupposes it was applied ("Given all edits from Tasks 1.1.1a, 1.1.1b, 1.1.2a, and 1.1.3a are applied"). The plan never states what "done" means if the optional task is skipped. Recommendation: either state plainly that 1.1.3a is in scope for this PR (and drop "optional" from the story title), or make Story 1.2.1's Given clause conditional on which tasks were actually applied.
- [ ] **`implementation/validation.md` (and the pre-existing `implementation/adversarial-review.md` this review overwrites) reference stale epic/story numbering that no longer matches `plan.md`.** validation.md's Requirement→Test Mapping table points to "plan Story 1.1.4" for verification and "if Epic 1.2 is implemented" for the CATALOG task; the old adversarial-review.md discusses an "Epic 1.3" for a `docs/syntax-rules.md` update. The current `plan.md` has none of that — verification is Story 1.2.1/Task 1.2.1a, the CATALOG task is Story 1.1.3, and there is no Epic 1.3 at all (that docs-update task was apparently cut after an earlier review round flagged it as ungrounded scope creep — consistent with `research/stack.md`'s own "optional... not required by any acceptance criterion" analysis of `docs/syntax-rules.md`). Recommendation: re-sync validation.md against the current plan.md's numbering before Phase 5 implementation starts, so nobody goes looking for a story that no longer exists.
- [ ] **This is the first `Finding.message` in the codebase to embed a URL** — verified via `grep -n 'message: format!' src/*.rs | grep -i http`, zero hits outside the two new sites. The Pattern Decisions table (plan.md line 58) cites `flag-argument`'s message (`src/rules.rs:865`) as precedent for the "inline literal, no lookup table" *mechanism*, which holds, but `flag-argument`'s citation is prose-only ("...Fowler's Remove Flag Argument: split into..."), with no URL — the URL-in-message convention itself is new, not an extension of an existing one. Not a defect, but the plan should say so explicitly rather than imply full continuity with an existing pattern; future Fowler-citation checks will likely copy whatever precedent this PR sets.
