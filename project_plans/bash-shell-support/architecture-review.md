## Concerns
- [ ] **Tech Debt Disposition, `rules.rs` row: justification is thinner than stated.** The plan says "no new instance of an existing violation". The file is 4490 lines (`wc -l`), but `mod tests` starts at line 2045, so about 2040 lines are production code and about 2450 are tests (VERIFIED `grep -n "mod tests"`). Eight language configs (`go_lang_config` at :948 through `rust_lang_config` at :1287) plus Bash sit in the same file as the checker engine, so each new language adds roughly 35-60 lines of table plus helper fns plus tests to one file. Bash added about 66 production lines and about 66 test lines (`git show --stat`: +132 in `e8a422a`, +66/-? in `1dc4dc3`). That is table growth, not logic growth, so "Extend as-is" is acceptable here. But "no hotspot output, file size is the proxy" is a weak basis, and the size proxy points the other way. Recommendation: reword the justification to "same responsibility growth, bounded per language", and add a follow-up: when the next language lands (or before), move the `*_lang_config` fns and their `fn` hooks into `src/checkers/rules/lang/<lang>.rs` (or `lang_configs.rs`), leaving the engine and `LangRuleConfig` in `rules.rs`. Run `code-hotspot-analysis` once so the next disposition cites data instead of line counts.
- [ ] **Tech Debt Disposition, `slog_key_predicate` row: rename trigger is miscounted.** The plan defers the rename "when a fourth language needs it". Today exactly two languages use the field (Go at `rules.rs:981`, Bash at `:1283`; VERIFIED by grep), so Bash is the *second* user, not the third, and the rule-of-three reasoning cited (Fowler) already fires at the next user. Reuse is acceptable to leave in this change: the field doc at `rules.rs:325-329` is already generic ("language-specific idiomatic exempt position"), and the exemption works per occurrence via `collector.slog_key_ids` (`rules.rs:207,1456,1625`). The cost of leaving it is a misleading name in a 19-line cluster (`grep -c slog_key` = 19, counting tests and docs; not 3 call sites as the plan says). Recommendation: correct the plan text to "second user; rename at the next user or in the next `rules.rs` touch", and note the collector field `slog_key_ids` and the doc at `rules.rs:205` need renaming together, or the rename is half-done.
- [ ] **`bash_is_expansion_string` ignores its contract at the call site.** It runs only for nodes already matched by `literal_kinds`, which for Bash includes `number`. A `number` node has no named children, so it returns false (`expansion_bytes > 0`). Correct, but that dependence on "no named children means not exempt" is implicit. Recommendation: one-line comment at the function, or a test with a number literal. Low cost.
- [ ] **Null-object hooks hide dead configuration.** `return_kind: "return_statement"` is a never-matching placeholder (plan C2), and `terminal_kinds: &[]` silently disables `unreachable-code`. The doc comment at `rules.rs:1236` names these, which is adequate, but nothing machine-checks that the disabled rules stay documented. Recommendation: make `return_kind` an `Option`/empty-string sentinel in the next `LangRuleConfig` change (Rust sibling configs would need the same edit), or add a test asserting which rules are inert for Bash so a future grammar bump that adds `return_statement` fails loudly.
- [ ] **Language fan-out guard is a process note only (plan "Tech debt and process lessons" 1, disposition row 3).** The unguarded sites were `hint.rs` (`Some(_)` wildcard) and the hard-coded glob count at `inline_ignore.rs:273`. Both are fixed for Bash, but the next language hits the same wildcard. Recommendation: replace `Some(_) => "//"` in `comment_leader` with an exhaustive match over `Language` (compiler-enforced), and add a test iterating `Language::ALL` that asserts a registered default check per language for `syntax-rules-*`, `comment-quality-*`, `*-file-size`. This also closes the plan's own admitted gap (no test pins `comment-quality-bash` / `bash-file-size` registration; T6 and T9).
- [ ] **Follow-ups list is incomplete.** Items found beyond the plan's 8-item list:
  1. Plan item 3 names `arch_export`/`arch_model`/`import_graph`/`declarations`/`lsp` as receiving `.sh` with zero symbols. `import_graph.rs:64-92` and `declarations.rs:108` select files per language with `files_for(files, Language::X)` and have no Bash entry, which is benign (no files fed to any language bucket), but that is "INFERRED benign" in the plan and confirmed here only by reading the filters, not by a test.
  2. The `Language`-to-check mapping lives in three separate hand-maintained places (`config.rs` glob lists, per-checker `file_globs()`, `file_size.rs`/`comment_quality.rs` name arms). The plan records the symptom (C7, C8) but lists no follow-up to derive globs from `Language::extensions()`. Add as a follow-up.
  3. `BashKind` is generated, vendored (2801-line JSON), and unused (`#[expect(dead_code)]`, `src/node_kind.rs`). Cost is build time and repo size for no consumer. Add a follow-up either to adopt typed kinds for Bash (the ADR-001 SEAM) or to stop generating unused kind enums.
  4. The `if_branches` first-two-children limitation (T12) is under-counting nesting for Bash; the plan lists it only under "Smaller items". It is a correctness gap for the rule's headline use case (installer scripts built from `if/elif/else`), so promote it to its own follow-up.
  5. The ADR-001 "<40% FP rate" gate is unmet (plan Backtest notes). The plan states it as the "main remaining gap" but the Open follow-ups list has no item for it; only the smaller "record triage" bullet. Add it explicitly, since `CLAUDE.md` says a checker without the corpus run is not done.
- [ ] **Testability / ADR gap: plan header says `ADRs: None`, but the plan's own Pattern Decisions cite "ADR-001 SEAM(typed-node-kind-migration)"** (VERIFIED: no `docs/adr/` directory exists in this worktree). Recommendation: either cite where ADR-001 lives or drop the reference, so a reader can verify it.
