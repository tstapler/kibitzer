# Pre-mortem: conditional-logic-smells
**Date**: 2026-11-03

## Failure Modes

| # | Failure | First Symptom | Prevention | Severity |
|---|---------|---------------|------------|----------|
| 1 | `condition_decision_count` counts zero operators on valid Go conditions because the tree-sitter Go grammar wraps `&&`/`||` as the node TYPE of `binary_expression`, not as a text child — the check never fires | Zero `decompose-conditional` findings across all backtest repos, including files with known long conditions | Before shipping, add an integration test that feeds a known 5-operator condition through the real tree-sitter Go grammar and asserts a hit; also run `kibitzer check native decompose-conditional` against one known file by hand and inspect the parse tree | P1 |
| 2 | `remove-control-flag` fires on every goroutine that captures a bool flag variable (e.g. `done := false; go func() { … done = true }()`), spamming false positives well above the 40% FP bar, but the implementer ships anyway after deciding the limitation is "acceptable" without running the formal backtest | FP rate on the backtest-corpus repos exceeds 40% but no one checks; users file issues day one; the check is disabled retroactively | Make the backtest gate non-optional in plan.md: the step "run `kibitzer check backtest remove-control-flag` and record FP rate" must appear as a checkbox gate before `default_checks()` wiring; require the number to appear in the PR body | P1 |
| 3 | `consolidate-conditional` fires on `if err1 != nil { return nil, err2 }` followed by `if err2 != nil { return nil, err3 }` — different error variables, so the return values differ, but the checker only compares the branch structure and misclassifies this as "consolidatable" | First run on any repo that uses idiomatic Go multi-error propagation (virtually every Go codebase) produces a flood of FPs | In `walk_consecutive_ifs`, compare the full return-value AST subtrees (not just the structural shape of the branch); add a fixture `testdata/consolidate-conditional/multi-error-propagation.go` that must NOT fire before the check ships | P1 |
| 4 | A future refactor moves `walk_dense_expressions` earlier in `check()` to share a loop with another checker, inadvertently placing `walk_consecutive_ifs` before the generated-file guard, so `consolidate-conditional` fires inside generated protobuf/mock files | First complaint from a user whose generated file gets annotated; or the backtest-corpus run against kubernetes (heavy on generated code) suddenly shows a spike in hits | Add a code comment directly above the `walk_consecutive_ifs` call: `// MUST remain after the generated-file guard; see ADR-001`; add a unit test that feeds a file beginning with `// Code generated by` and asserts zero findings from every new check | P2 |
| 5 | `consolidate-conditional` guard-clause suppression uses a heuristic (single-statement body, early return) that is too broad, suppressing legitimate consolidation opportunities in hot paths — the check's recall drops so low that users never see it fire in real code, making it effectively dead on arrival | Backtest transcript replay shows near-zero true positives on real edit history; users report the check as "never fires" | Backtest the suppression heuristic specifically: run the check with suppression disabled against the corpus, compare hit counts with suppression enabled, and require the recall drop to be < 50% (i.e. suppression removes fewer than half the hits); document the threshold in plan.md | P2 |

## P1 Items (address before implementation)

- [ ] **Grammar assumption unverified** — verify empirically (parse a known file, inspect the AST node structure for `&&`/`||`) that the Go tree-sitter grammar exposes operator text as a child text node of `binary_expression` before writing `condition_decision_count`; if not, switch to matching the node type `"&&"` or `"||"` as child node kinds rather than `.text()`.
- [ ] **Backtest gate is mandatory, not advisory** — add an explicit checkbox to plan.md: "FP rate from `kibitzer check backtest <name>` recorded in PR body, confirmed < 40%" must be checked before each rule is added to `default_checks()`; treat a skipped backtest as a blocking review comment.
- [ ] **Multi-error propagation FP in `consolidate-conditional`** — add `testdata/consolidate-conditional/multi-error-propagation.go` with consecutive `if errX != nil` guards returning different error values; this fixture must produce zero findings before the check ships; update `walk_consecutive_ifs` to compare full return-value subtrees, not just branch shape.
