# Adversarial Review: go-package-focus
**Date**: 2026-10-23
**Verdict**: CONCERNS

## Blockers

- [x] **AC-6 has no implementing story, so the FP threshold gate in Story 2.1.4 has no evidence path.** AC-6 requires comparing size-only, graph-only, and combined evidence leads against adjudicated cases and recording acceptance/rejection reasons before claiming precision or selecting thresholds. No story in Phases 2–4 does this comparison. Story 2.1.4 says wiring into `default_checks()` is deferred pending "owner approves FP rate" — but the plan provides no mechanism to generate the comparison data that would inform that approval. The feature as described cannot satisfy AC-6 and cannot complete Story 2.1.4 without undescribed work. **Recommendation**: Add a story (between Stories 2.1.3 and 2.1.4) that runs the three evidence modes against the corpus backtest targets and records adjudication results; make that story's output the evidence base for the FP rate approval gate.
  **Resolution**: Story 2.1.5 added with Tasks 2.1.5a (three-mode comparison against fixtures and corpus packages, accept/reject/abstain table) and 2.1.5b (adjudication + threshold documentation in `docs/go-package-focus.md`); Story 2.1.4 now explicitly gates on Story 2.1.5's documented adjudication.

- [x] **The Union-Find clustering edge definition is absent.** Story 2.1.2a says "intra-package symbol clustering using Union-Find" but Union-Find is not a complete clustering algorithm on its own — it only merges elements; the algorithm's quality is entirely determined by what defines an edge (i.e., when two symbols are placed in the same cluster). The plan never states which ArchModel signal establishes an edge: shared field accesses (as in `extract_class.rs`), call edges, type edges, or some combination. A developer implementing Story 2.1.2a must make a significant undocumented architectural decision that directly determines whether the checker produces useful or noisy results. **Recommendation**: Before implementation, specify the edge definition in the plan (e.g., "two symbols are in the same cluster if they share at least one field access or a direct call edge"). Also state whether any quality threshold analogous to `extract_class.rs`'s `MIN_ENTITY_PLACEMENT_SCORE` is applied to filter out weak clusters before surfacing a finding.
  **Resolution**: Task 2.1.2a now specifies: resolved `call_edges` only (excluding unresolved); all `field_accesses`; type super-node collapse before clustering; quality threshold of >= 2 components each with >= 2 type-level nodes; `MIN_SYMBOLS_FOR_CLUSTERING = 6` at the type-node level post-collapse.

## Concerns

- [ ] **Model cache thrashes when `go-package-focus` runs alongside other `ArchModelChecker`s in batch mode.** `ModelCache` is a single-slot cache keyed by `(repo_root, include_private)` (verified in `src/arch_model.rs:1008–1034`). `go-package-focus` overrides `needs_private_symbols()` to `true`; every existing `ArchModelChecker` uses the default `false`. In any batch run that includes both `go-package-focus` and another architecture checker (e.g. `InstabilityChecker`), the single cache slot will be invalidated and rebuilt once for each distinct `include_private` value — doubling model build time. For a large repo like `kubernetes/kubernetes`, a full model parse is expensive. **Recommendation**: Either document this as a known cost, or investigate whether `go-package-focus` can work with the public-symbols model supplemented by a targeted private-symbol lookup rather than requiring a full private build.

- [ ] **No quality gate on Union-Find split proposals.** `extract_class.rs` gates candidates behind `MIN_ENTITY_PLACEMENT_SCORE = 0.75` (the fraction of methods that are unambiguously placed), filtering out weak splits. The plan has no analogous quality gate for `go-package-focus`. A Union-Find partition over field-access or call edges will produce a cluster for any package with more than one symbol that has any edge, including one shared access. Without a quality threshold, the checker will surface trivially-weak splits (e.g. a package with two functions that each use one field but happen to not cross-access) as advisory findings, driving up the FP rate and reinforcing the FP threshold gate that already has no evidence path. **Recommendation**: Specify a minimum cluster-quality score (cohesion ratio, edge density, or equivalent) that must be met before a partition is surfaced as a finding.

- [ ] **No story verifies `go-package-focus` doesn't duplicate `extract_class` findings on the same package.** AC-2 explicitly prohibits "labeling an Extract Class finding as a package decomposition finding." The glossary notes the distinction, but no story or acceptance criterion verifies that the two checkers don't fire on the same package for the same underlying signal (low LCOM / field-access clustering). A reviewer reading two advisory findings about the same package — one from `extract_class` recommending a type split and one from `go-package-focus` recommending a package split — with no explanation of the relationship has no actionable signal. **Recommendation**: Add an acceptance criterion to Story 2.1.3 that verifies on at least one synthetic fixture: when `extract_class` would fire, `go-package-focus` either doesn't fire, or if it does, the finding text explicitly notes the relationship to the `extract_class` finding.

- [ ] **Build-cost cold/warm/edited-source workflow comparison (AC-7) has no implementing story.** AC-7 requires "compare cold/warm/edited-source workflows." Story 3.1.1 only implements the version gate and JSON parse output. The comparison of the three workflow types — which is the justification for having the build-cost collector at all — is absent. **Recommendation**: Add a task to Story 3.1.1 (or a new Story 3.1.2) that documents an actual comparison run showing the output differences across cold/warm/edited-source, even if only in the docs rather than as automated test coverage.

- [ ] **`-debug-actiongraph` JSON schema changes in future Go versions are not guarded.** The version gate (`>= go1.19`) only confirms the flag exists. If the JSON schema changes in a Go 1.25+ release, `kibitzer go build-cost` will silently parse wrong data with no diagnostic. The "degrade gracefully" behavior in ADR-002 applies only when the flag is absent, not when the schema drifts. **Recommendation**: Bound the version range above (`>= go1.19 && <= go1.24`) and emit the same diagnostic for newer-than-tested versions until the schema is validated against them; or add a required field presence check on parse that fails loudly rather than silently.

## Minors

- No per-package symbol cap is specified for Union-Find clustering, unlike `extract_class.rs`'s `MAX_METHODS_FOR_CLUSTERING = 80`. The existing `union_find.rs` explicitly notes it has no union-by-rank/size and is intended for "at most a few dozen elements." A large generated type package (e.g. `kubernetes/kubernetes`'s `types` package with hundreds of symbols) could produce O(n²) union operations. Specify a cap.

- `go-package-size` is already in `default_checks()` as a whole-repo architecture checker. Any package that triggers `go-package-size` is a prime candidate for `go-package-focus`. With both in `default_checks()`, the same package will produce two advisory findings with overlapping motivation and no cross-reference between them. Consider whether `go-package-focus` should suppress or reference `go-package-size` findings on the same package.

- The "contrary evidence" requirement in AC-3 ("each finding must include contrary evidence") has no test fixture in Story 2.1.3. The cohesive-large-parser fixture tests the negative case (no finding), but no fixture verifies that a positive finding correctly includes a "why not split" section when contrary evidence exists (e.g., a shared lock that crosses the cluster boundary). This leaves AC-3's contrary-evidence requirement untested in the fixture suite.

- AC-6 comparison results (the adjudicated cases and their reasons) have no documentation home in Phase 4. `docs/go-package-focus.md` covers AC-8 (the split/keep decision procedure) but not the empirical record of how the three evidence modes performed. If the comparison is done as part of Story 2.1.4a (corpus backtest), its output should be persisted somewhere (e.g., `docs/backtest-triage/go-package-focus.md`) rather than existing only in a terminal session.

- The "kibitzer go build-cost subcommand grouping" unresolved question has no fallback or default stated. If the owner is unavailable or the decision is deferred, Phase 3 cannot begin. The plan should state a default CLI shape (e.g., `kibitzer go build-cost <dir>` as a top-level subcommand with a Go sub-subcommand as the alternative) so implementation can proceed without blocking.
