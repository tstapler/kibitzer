# Pre-mortem: go-package-focus
**Date**: 2026-10-23

## Failure Modes

| # | Failure | First Symptom | Prevention | Severity |
|---|---------|--------------|------------|----------|
| 1 | `fan_in_out` dedup silently drops or changes coupling/instability findings on real repos without users knowing, because existing tests only cover distinct-pair edges and there are no golden files to detect the shift | A corpus run before vs. after the fix shows different finding counts per checker, but the backtest-triage.py output is interpreted as "expected inflation removal" when some changes are actually behavior regressions on repos that use multi-file imports in non-trivial ways | Add a golden-output snapshot for at least two corpus repos (kubernetes, ripgrep) **before** the fix lands — store the full finding set so the post-fix diff is reviewable rather than assumed clean; mark each disappeared finding as "expected dedup reduction" or "investigate" | P1 |
| 2 | `go-package-focus` FP rate on monorepo entry-point and wiring packages (kubernetes `cmd/*`, deno integration packages) is too high to pass the corpus backtest gate, so the check is never wired into `default_checks()` — the feature ships but no user ever sees it without manual opt-in | Story 2.1.4a corpus backtest shows 60-80% FP rate on kubernetes; Tyler cannot approve the FP threshold without a second data point showing the signal improves with tuning, and the cycle repeats | Story 2.1.3a must add an explicit "entry-point/wiring package" suppression heuristic (e.g., fan-out exceeds a secondary ceiling → emit `[entry-point, not a split candidate]` informational finding instead of advisory) before the corpus backtest; this is not in the current plan | P1 |
| 3 | `ModelCache` single-slot thrash doubles model build time for any batch run that includes both `go-package-focus` (needs `include_private=true`) and any other `ArchModelChecker` (needs `false`), making kibitzer's architecture assessment unusably slow on repos like kubernetes — users disable the check to recover performance | A `kibitzer architecture assessment` run against a mid-size repo takes 2-3× longer after the new checker is wired into `model_registry()` with no message explaining why | Document the cache cost explicitly in Story 2.1.1b's wiring task and either (a) investigate whether `go-package-focus` can be split into a private-symbols pass + public-model supplemental lookup to avoid full private rebuilds, or (b) add a `--skip go-package-focus` escape valve with a performance note in `docs/go-package-focus.md` | P2 |
| 4 | `-debug-actiongraph` JSON schema changes in Go 1.25+ cause `kibitzer go build-cost` to silently return 0 cache hits and 0 actions (no parse error, just wrong data) — users make caching decisions based on garbage metrics for months before noticing | A Go upgrade lands; `kibitzer go build-cost` reports cache-hit ratio 0% on a warm cache; no error or version warning is printed | Bound the version range at both ends in the version gate: `>= go1.19 && <= go1.24`; emit `go-package-focus: -debug-actiongraph schema unvalidated for Go 1.25+; run kibitzer go build-cost --version-check to confirm` for out-of-range versions; add a required-field presence check on parse that returns a hard error on unexpected schema shape rather than zero-value defaults | P2 |
| 5 | Union-Find clustering has no symbol cap, and `union_find.rs` is documented for "at most a few dozen elements"; a proto-generated types package in kubernetes with 200+ distinct types triggers O(n²) union operations, hanging kibitzer for 5+ minutes on a corpus backtest run | `kibitzer run kubernetes/kubernetes` starts and never finishes; the process is alive but no output is produced; user kills it and disables the check | Add `MAX_TYPE_NODES_FOR_CLUSTERING = 60` (analogous to `extract_class.rs`'s `MAX_METHODS_FOR_CLUSTERING = 80`) at the type super-node level after collapse; packages exceeding the cap emit a `[too-large-to-cluster, N type-nodes exceeds cap]` informational finding and skip clustering | P3 |

## P1 Items (address before implementation)

- [ ] Failure #1 (fan_in_out silent regression) — Before landing Task 1.1.1a, run `kibitzer architecture assessment` against kubernetes and ripgrep and save the full finding sets to `docs/backtest-triage/fan-in-out-before.txt`; repeat after the fix and diff; every changed finding must be individually classified in the commit message as "expected dedup reduction" or "needs investigation." Do not proceed to Phase 2 with any unclassified changes.
- [ ] Failure #2 (entry-point FP rate blocks default_checks()) — Add an "entry-point wiring package" detection heuristic to Story 2.1.3a before the corpus backtest: when a package's total fan-out exceeds a secondary threshold (e.g. 20 distinct imported packages) and the clustering signal is driven entirely by cross-package call edges (no shared field accesses), emit `[likely entry-point, not a split candidate]` informational rather than an advisory finding. Without this, Story 2.1.4a's FP gate will fail and the feature will be permanently stuck in `model_registry()` only.
