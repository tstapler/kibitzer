# Pre-mortem: test-effectiveness-critique
**Date**: 2026-10-11

Basis: `implementation/plan.md` (including its Repair log), `requirements.md`, and a skim of `adversarial-review.md`. Failure is imagined at three months after kickoff. Plan line numbers cited below are from `plan.md` at this date.

## Failure Modes

| # | Failure | First Symptom | Prevention | Severity |
|---|---------|--------------|------------|----------|
| 1 | The experiment returns null or negative (H2 not beaten vs N4, H3 not supported, every static rule below the H4 floor) and the plan has no defined deliverable for that outcome. G2 offers only "keep research-only", which deletes the hidden `Command::Tests`, so ~51 stories of ingest infrastructure become dead code and Success Metric 4 ("at least one shipped check or report") is unmet. | G1/G2 decision files all read "drop"/"keep research-only"; owner asks "so what shipped?"; Phase 2 code has no caller. | Add an outcome table to Story 0.4.1 and Story 3.4.1, fixed at G0: for each combination of {static promote / none} x {H2 pass / fail} x {H3 supported / not}, name the shipped artifact. Minimum guaranteed deliverable regardless of result: `docs/test-effectiveness.md` with the negative result, plus the ingest-only report kept as an unhidden, tier-free "descriptive" command (unique coverage and joint-loss counts with non-validation banner, no ordering claims). Reword Success Metric 4 in the plan so that "report shipped with measured negative validity" is an accepted terminal state, and change Story 3.4.1's "remove the variant" branch to "keep descriptive-only" unless the owner explicitly says remove. | P1 |
| 2 | The validation is circular, so a green result carries no information. `JointSafe` is by definition the subset with empty joint loss of coverage units (and of kills where available), so H1's coverage delta is 0 by construction, and N4 (coverage-preserving random deletion) also scores 0. On kill-matrix arms (PIT/Stryker) the mutation-score delta over the same mutants is also 0 by construction. Only the held-out proxy (P2 same-family, P1 if powered) can discriminate. If spike 0.3.4 pushes most arms to "coverage-delta only", H1 passes on every arm and the write-up reads as validated. | H1 reported "equivalent to zero" with CI width 0.0 on every arm; H2 vs N4 p-values hover near 0.5 (flagged set and N4 are both coverage-preserving); owner celebrates H1. | Patch Stories 3.1.1 and 3.3.3: (a) reclassify H1 as a harness sanity invariant ("must be exactly 0 for coverage, and 0 on sampled mutants for kill-matrix arms; nonzero means a harness or joint-loss bug"), not evidence of validity; (b) make the held-out proxy result (H2 vs N2 and N4 on P2/P1, never on the selection data) the only statement that may be called "validated"; (c) in Story 3.3.3 require every results row to state "selection data vs evaluation data" and the label same-family / real; (d) a coverage-delta-only arm is reported as "no validity evidence" in the results table, not as an H1 pass; (e) add the invariant check to the Story 3.1.2 acceptance criteria. | P1 |
| 3 | Corpus and mutation runs are infeasible on the owner's machine. The cost model T = (2 + N_nulls x K_mut) x M_s_killed x t_m with N_nulls=3 and K_mut>=19 is ~59 x M_s x t_m; at t_m of seconds and M_s of hundreds this is tens of hours per arm. Stories 3.2.x are priced in tokens (~230-300k CU each), not wall-clock, and the plan's re-baseline is "required" but has no stop-loss. Result: most arms degrade to coverage-only (feeds #2) and the owner stops babysitting. | Spike 0.3.4 memo shows T above the cap for every non-PIT/Stryker arm; first 3.2.x arm runs for days; arms silently dropped. | Add to Story 0.4.1 an owner-time and machine-time budget (total wall-clock hours the owner will let corpus runs occupy) and an explicit stop-loss: after each arm, if actual wall-clock exceeds 1.5x the 0.3.4 projection, stop and record the arm as "not run: budget". Order arms by information per hour (PIT/Stryker matrix arms first, since nulls are free from the matrix at K>=999). Require the Phase 3 estimate rows to carry a wall-clock column filled from 0.3.4 before G0. | P2 |
| 4 | Tool-install or exemplar failure leaves Q3 unanswerable (n < 2 per-test kill-matrix suites). Candidates in Story 0.2.2 are INFERRED; the only listed local Java build path is Gradle (`mvn` absent), PIT/Stryker have no fallback tool in Story 0.3.4 (only Go and Python do), and `commons-lang` may be Maven-only. | Task 0.2.2a records "fail" on criteria (1) or (4) for every JVM or JS/TS candidate; Task 0.3.4a install errors. | Time-box Story 0.2.2 and 0.3.4a install attempts by a G0-stated cap, add a third candidate per JVM/JS language and a named fallback (PIT Maven plugin, a Gradle-based project such as `google/gson`, Stryker on a plain-Jest utility), and state the n=0/n=1 consequence in Story 3.3.2: "Q3 not answered; kill-primary where a kill dimension is present; coverage-only ordering labeled unvalidated everywhere" (the Story 4.2.1 "not supported" branch already covers rendering). | P2 |
| 5 | Ingest adapters drift from tool schemas. Fixtures come from a single real run per tool (2.2.4, 2.2.5), and `MissingProvenance` checks only tool and version presence. A coverage.py, Stryker (`schemaVersion`), or PIT XML change, or a different runner/bail setting, parses without error but misattributes tests, giving confident wrong findings. | Report on a newer tool version shows implausibly many zero-unique-coverage tests or a `KillCompleteness::Full` claim on a bail-on-first run; golden tests still pass. | Add to Stories 2.2.1, 2.2.4, 2.2.5: an allow-list of schema/format versions per adapter, with an unknown version producing a class-W warning and capping every finding from that dimension at `Low`; record the tool version in each fixture directory and add one fixture per major version where available; add a plausibility check (fraction of tests with identical coverage, fraction of killed mutants with exactly one killer) that warns when out of expected range; schedule the producer-run fixture refresh as a task in the Story 4.2.2 docs pass. | P2 |
| 6 | Static checks are too noisy to promote. Helper-assertion resolution is same-file and bounded depth; a call into another file that does not receive the framework handle (Python `helpers.check_x()`, Java static imports, Kotlin extension asserts, Rust macros) reads as "no assertion". The H4 floor (0.80 Wilson lower bound over >= 50 findings per rule per language) fails for most language/rule cells, so G1 promotes nothing. | First Story 1.2.2 triage on Python/Java shows "assertion in helper in another file" as the dominant FP mode. | Re-sequence Epic 1.1/1.2: deliver Go and Python for `test-no-assertion` only through Story 1.2.2 triage before writing Stories 1.1.3, 1.1.4 and the Java/Kotlin/TS/Rust rule tables, so noise is measured at 1/3 of the build cost. Add a precision-first mode for unresolved calls: any unresolved call whose callee name or import path matches an extendable assertion-ish pattern (`assert|check|verify|expect|require|must`) counts as asserting, and the mode is measured in 1.2.2 against the strict mode. Record in G1 per language, not per rule. | P2 |
| 7 | Agents game or rubber-stamp the checks (Goodhart). The hook prints a copy-paste `kibitzer:ignore <rule> -- <why>` line (Story 1.1.2), and the assertion-padding behavior is itself UNVERIFIED in research. Agents respond to `test-no-assertion` with `assert result is not None` or `assert True`-adjacent weak oracles that pass both `test-no-assertion` and `test-tautology`, or with boilerplate ignore reasons, so findings go quiet while test quality does not improve. | Transcript backtest shows ignore directives with generic reasons ("intentional") added in the same turn as the finding; weak-assertion share rises after the check ships. | Add to Story 1.2.1 two measurements before G1: (a) rate and reason diversity of `kibitzer:ignore` added in the turn immediately after a finding, and (b) share of fixes that add only `not None`/`len > 0`/truthiness assertions. Add a weak-oracle fixture family to Story 1.1.1 labeled as known false negatives, and make G1 record the measured (a) and (b). Do not widen the checker to chase (b) without that evidence; if (a) is high, drop the pre-filled directive from hook-mode output and keep it in `kibitzer run`. | P2 |
| 8 | Spend is front-loaded on product surface before validity is known. Phase 2 (matrix, six adapters, locator, staleness, brief, enrichment, R1-R22 messages, `--by-package`) is built in parallel with Phase 1 and before G0/G2, though only `coveragepy`, `gocover`, `pit`, `stryker` and the analysis core are needed by the experiment. Under outcome #1 the rest is waste; under a late G0, it delays the experiment that is the actual risk. | Phase 2 stories reach "done" while G0 is still unrecorded; Phase 3 start slips behind adapters nobody needs yet. | Split Phase 2 in the dependency diagram and Effort table into "experiment-critical" (2.1.1, 2.1.2, 2.1.4 minimal, 2.2.1, 2.2.2, 2.2.4, 2.2.5, harness input path) and "ship-gated" (2.2.3, 2.2.6, 2.3.3, 2.3.4, 2.3.5, 2.3.1c message table, `--by-package`, staleness), and list `G2-decision.md` as a precondition for the ship-gated set. | P2 |
| 9 | Precision figures that set tiers and G1/G2 rest on agent-assigned triage verdicts. Story 3.3.1 and 1.2.2 have the agent record "intent" verdicts (regression pin vs spec vs distinct contract) that are inherently judgment calls; owner "spot-checks". The H4 floor and `ConfidenceTier` boundaries are then computed on noisy, possibly optimistic labels (the plan itself estimates ~900 verdicts, "likely 2-3x under"). | Owner overrides a large fraction of sampled verdicts on first spot-check; tier precision drops sharply after the owner labels a larger sample. | Add to Stories 1.2.2 and 3.3.1: owner independently labels a fixed, seeded random 10% (min 30 per rule/arm) blind to the agent's verdict, agreement is reported, and Wilson bounds in G1/G2 are computed only on owner-confirmed labels (or on agent labels with the measured disagreement stated). Cap triage volume at what the owner has committed in G0 instead of the 2-3x-uncertain count. | P2 |
| 10 | The ranked output is treated as a delete list by an agent or automation via `--format brief` or the hook channel, and regression pins or spec tests are deleted at scale, despite advisory wording. Less likely because the report is hidden and advisory, but the effect would be reputational and irreversible in the user's repo. | A downstream transcript or PR deletes tests citing the brief; JointSafe list used verbatim. | In Story 2.3.4 make the brief's `non_claims` and `verify_first` mandatory non-empty fields, add a `"action": "review"` constant and no "delete"/"remove" wording anywhere in the schema, and add a test for banned imperative verbs across all report formats (not only the hook text of Story 1.1.2). | P3 |
