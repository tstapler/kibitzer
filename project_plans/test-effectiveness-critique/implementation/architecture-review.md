## Concerns
- [ ] Story 2.3.2 / Task 2.3.2a — "`src/inline_ignores/` (consumer only)" is wrong. `kibitzer:ignore test-zero-unique-coverage` is judged by `known_rule()` (`src/inline_ignores/rules.rs:136`), which knows only `RULES` plus registered checker names. The batch-report rule ids are neither, so `kibitzer run` on that file emits `[unused-ignore] 'test-zero-unique-coverage' is not a known rule or checker` (`src/inline_ignores/unused.rs:146`). Recommendation: add the report's `Signal` rule ids to `RULES` as `OwnerMatch::Unowned` (as `god-class` is), add `rules.rs` to the Story's Files, and add an AC "directive is not reported unused/unknown by `kibitzer run`". Mind the drift-guard test named in the `RULES` doc comment.
- [ ] Stories 2.2.1-2.2.5, 2.1.3b, 2.3.2, 2.3.4 — no component maps `TestId (file, qualified name)` to a source file and function line. Inputs do not carry that: Go per-test profiles are named `<TestName>.out` (ambiguous across packages at kubernetes scale), coverage.py contexts are dotted module paths, PIT gives class/method names, Stryker gives opaque test names plus `testFiles`. Yet kind tagging, `kibitzer:ignore` anchoring, and the adjudication brief all need the line. Recommendation: add a named story "TestLocator" (`src/test_effectiveness/locate.rs`): resolve `TestId` against the repo using `TestCodeProfile` plus tree-sitter, return `Located | Ambiguous | NotFound`, and make `NotFound` an `ExclusionReason`. Change the Go recipe to encode the package path in the profile name or manifest.
- [ ] Story 2.1.1 / Glossary `TestMatrix` — one `Provenance` and one `Attribution` per matrix does not fit the report taking coverage and mutation inputs together (Story 2.3.1). `Attribution::{Isolated, InOrder, LeaveOneOut}` is meaningless for a kill matrix. PIT `coveringTests` is mutant-site coverage, not line coverage, which weakens the Q3 Jaccard comparison (Story 3.3.2). Recommendation: model dimensions separately, for example `TestMatrix { coverage: Option<Dimension<CoverageUnit, CoverageAttribution>>, kills: Option<Dimension<MutantId, KillCompleteness>> }`, each with its own `Provenance`, where `KillCompleteness` is `Full | FirstKillerOnly` (this also types the Stryker/PIT truncation warnings). State in Story 3.3.2 which coverage unit each arm compares.
- [ ] Story 0.2.1 / Stories 1.1.2-1.1.4 — `TestCodeProfile` lists a "test-function predicate" and vocabularies but no shared function-level API. Three checkers x six languages would each re-walk the tree and re-implement assertion-call extraction (callee name, operands), which is the duplication the seam exists to prevent. Also `assertion_helpers` arrives via per-check `configure(&options)` (Task 0.2.1c), so a user must repeat it on three checks and the report cannot see it. Recommendation: the seam exposes `test_functions(&CheckContext) -> Vec<TestFn { name, line, body, kind }>` and `assertion_calls(&TestFn) -> Vec<AssertionCall { callee, args }>`; specify one shared options key resolved once, and say how the report gets it (read `.kibitzer/inspect.json` check options for `test-no-assertion`, or a `--assertion-helper` flag).
- [ ] ADR-004 decision 3 / Story 1.1.2 AC3 — the claim "only nudge on tests added or touched in the diff" is stronger than the mechanism. Anchoring on the function's first line passes `scope_line_verdicts` (`src/check.rs`) only when that line is in a changed range. An edit that deletes assertions inside an existing test body is not flagged (that is Story 4.1.2, conditional). Recommendation: reword the ADR title and Consequences to "added or signature-touched", and cross-reference 4.1.2 as the only coverage for body edits.
- [ ] Story 1.1.5 / Task 1.1.5a — "registered in the checker registry" is imprecise: registration is `inventory::submit!` in each checker module (`src/checker.rs:247`), and `src/checkers/mod.rs` needs only `pub mod`. Opt-in precedent exists (`prose_checks()` doc comment, `src/config.rs:784`). Recommendation: the story should state `test_quality_checks()` returns `Check` entries that nothing chains, with the checkers reachable via `inventory`, and cite that precedent. Verify `kibitzer check list` lists them (AC for 1.1.4 already asks this).

## Nitpicks
- Plan says `Commands::Tests`; the enum is `Command` (`src/main.rs:71`). Batch-report precedent lives under `ArchitectureAction`; ADR-002 already justifies the top-level `tests` verb, so no change, just fix the name.
- Story 1.2.1 uses `--introduced-only`; the real flag is `--only-new` (`src/main.rs:308-310`).
- `src/test_code.rs` (shared seam) would import `checkers::file_size::is_generated`, a dependency from a lower-level module into `checkers`. Move or re-export `is_generated` into `test_code`/a neutral module, or accept as pre-existing.
- Story 4.2.1 unit test that parses constants out of `docs/test-effectiveness.md` couples code to prose layout. Prefer constants in code plus a doc table generated or checked in the other direction (doc cites the constant names).
- Phases 1 and 2 both add `mod` lines to `src/main.rs`; `src/main.rs` has 49 six-month commits, so land the module declarations in Wave 1 (Story 2.1.1 already does) to avoid the merge conflict `default_checks()`'s doc comment describes.
- Tech Debt Disposition cites no hotspot score; add the churn counts above (`main.rs` 49, `config.rs` 36, `check.rs` 30) to justify "Isolate via seam" and "Extend as-is".
- Rust `#[cfg(test)]` unit tests are inline in production files, so `is_test_file` is not meaningful for Rust; the profile needs per-function detection only. State this in Task 0.2.1b.
