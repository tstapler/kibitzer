# Pre-mortem: affected-tests
**Date**: 2026-09-22

## Failure Modes

| # | Failure | First Symptom | Prevention | Severity |
|---|---------|--------------|------------|----------|
| 1 | A `Modified` file whose logical package changes without `git mv` (e.g. an edited `package` clause during a manual code move) is resolved only via its current on-disk location (Story 2.2.1); `resolve_removed_path` is wired solely for `Deleted`/`Renamed`-old paths (Task 2.2.2b), so the *old* package's former importers are never re-seeded and no bail-out fires — this is `Modified`, not `Deleted`/`Renamed`. | A stapler-squad PR that refactors a package boundary (common during cleanup work) passes CI green; a caller of the pre-refactor API that was never updated breaks in production because its test package was never selected to run. | Add a cheap content-level check: if a `Modified` Go file's diff hunk touches its `package` line, treat it as a bail-out trigger (or at minimum resolve it via *both* its old and new package identity, requiring a lightweight pre-image read) rather than silently trusting the post-change location. Land this as a new Story under Epic 2.2 with its own acceptance criteria, not just an ADR-001 prose caveat. | P1 |
| 2 | `import_graph.rs`'s `find_go_mod_upward` (no `replace`-directive support) misattributes package identity for files under stapler-squad's own nested modules (`tuitest/go.mod`, `tools/scanner/go.mod`, `tools/lint/go.mod`, per requirements.md:426-427) — a plain code edit inside one of those directories (not touching `go.mod` itself, so the bail-out glob never fires) produces import edges anchored to the wrong module root, so `reverse_bfs` misses a real importer that only resolves via a `replace` directive. | A change inside `tools/scanner/` (or similar) doesn't trigger re-testing of the root-module package that depends on it via `replace`; that dependent package's regression ships to `main` undetected, discovered only later via an unrelated bug report. | Add a Phase 4 fixture that mirrors stapler-squad's actual multi-`go.mod` layout (3+ nested modules, at least one `replace` directive) and assert what `affected` actually computes for a change inside a nested module — today no test exercises more than one `go.mod` in the same repo. Also change Task 4.1.3a from "sample a `replace`-directive commit *if one exists* in history" to "construct one deliberately against the target repos's real module layout" so this risk gets a real answer instead of an opportunistic one. | P1 |
| 3 | The literal `PKGS=""` / unquoted `$(...)`-expansion contract (requirements.md:264-270, Story 3.2.2's empty-stdout case) means a truly empty affected set collapses `go test $PKGS` to bare `go test` in the CI wrapper that word-splits it — Bash drops the empty variable entirely, so the command silently becomes "test whatever package `cwd` resolves to," not "run nothing." No task in the plan spawns the actual CI-shaped invocation (`go test $(kibitzer ...)`) for the empty case; Task 3.2.2c only asserts kibitzer's own stdout is empty, not what a downstream shell wrapper does with that emptiness. | A no-op-for-Go diff (e.g. a comment-only or doc-only change) either errors confusingly ("no test files") or silently reports a trivial pass for whatever package the CI runner's cwd happens to be, masking that CI intended to skip testing entirely — the one case this feature's contract explicitly claims is safe. | Add an acceptance criterion/task that spawns the exact shell shape stapler-squad's `build.yml` uses (`PKGS="$(kibitzer architecture affected ...)"; go test $PKGS`) for the zero-affected-packages case and asserts the observed behavior is intentional — either kibitzer's contract changes (e.g. never emit pure-empty stdout, use a `__NONE__` sentinel the wrapper checks for) or `build.yml`'s eventual cutover diff must add an explicit `[ -z "$PKGS" ] && exit 0` guard, documented now rather than discovered during the stapler-squad cutover PR. | P1 |
| 4 | Story 4.1.3's real-diff comparison against `test-affected.py` is a one-time, hand-run exercise (`docs/affected-validation.md`) with no automation re-running it — flagged as an unresolved Concern in the adversarial review but still unaddressed by any task. A later change to `import_graph.rs`/`arch_model.rs` (e.g. landing a new native checker that touches shared graph-building code, as PR #94/#95 already show happens routinely) silently changes `affected`'s output with nothing to catch it. | Weeks or months after shipping, a stapler-squad PR that should have triggered broader test selection passes CI narrowly; the connection to an intervening kibitzer change is only found by manual archaeology, if at all. | Convert the 10+ validated commit/output pairs from Task 4.1.3b into committed golden fixtures (a new `tests/affected_regression.rs`, or synthetic repo fixtures with pinned expected `AffectedResult` values) that run in kibitzer's own `cargo test` on every PR touching `affected.rs`, `import_graph.rs`, or `arch_model.rs` — turning the validation doc into a guardrail instead of a point-in-time artifact. | P2 |
| 5 | The performance NFR ("no slower than `test-affected.py`") is validated once, at today's repo size, via manual `time` on ~10 commits (Task 4.1.3b/c) — with no stated threshold for revisiting and no periodic re-check. The design rebuilds the full `ArchModel` (tree-sitter parse of every source file) on every invocation (Task 3.1.1b step 5), which doesn't have `go list`'s incremental build-cache advantage, so its relative cost is likely to grow faster than `test-affected.py`'s as stapler-squad's file count grows. | PR-time CI duration creeps up over successive months; nobody connects the regression to `affected` because `docs/affected-validation.md` already says "NFR met" and nothing re-checks it. | State an explicit trigger condition in `docs/affected-validation.md` (e.g. "re-run this comparison if stapler-squad's tracked Go file count grows by 50%, or if a single invocation exceeds N seconds") that pulls the already-scoped-out daemon-cache-reuse follow-up back into consideration, rather than treating the one-time measurement as permanent proof. | P2 |

## P1 Items (address before implementation)
- [x] #1 — Resolved: new Story 2.2.3 (`plan.md`) detects a `Modified` Go file's `package`-clause change via diff-hunk inspection and routes it through `BailOutReason::PackageClauseChanged`; ADR-001's Consequences section now names this a closed gap, citing Story 2.2.3.
- [x] #2 — Resolved: Task 4.1.3a (`plan.md`) rewritten to construct a synthetic 3+-nested-module fixture (mirroring stapler-squad's real `tuitest/`/`tools/scanner/`/`tools/lint/` layout) with a `replace` directive and assert `compute_affected`'s actual output, instead of opportunistically sampling real history.
- [x] #3 — Resolved: Story 3.2.2 (`plan.md`) adds an acceptance criterion + Task 3.2.2d exercising the exact `PKGS="$(...)"; [ -z "$PKGS" ] && exit 0 || go test $PKGS` shell shape for the zero-affected-packages case; kept bare-empty-stdout (matching `test-affected.py`'s contract exactly) and made the wrapper-side guard a documented hard requirement in plan.md's Risk Control section.

## Summary
3 P1 items, 2 P2 items, 0 P3 items.

Top failure mode: the single-working-tree-snapshot design (ADR-001) still lets a package-identity change made without `git mv` — a `Modified` file whose `package` clause changes — slip through as neither a resolved rename nor a bail-out, silently dropping the exact "never silently under-test" guarantee this whole project exists to provide.
