# Pre-mortem: kibitzer — Native Architecture Linting
**Date**: 2026-08-22

## Failure Modes

| # | Failure | First Symptom | Prevention | Severity |
|---|---------|--------------|------------|----------|
| 1 | Config-authoring friction plus advisory-only zero-match handling combine to make misconfiguration silently invisible: a typo'd `Component.paths` glob produces a `[component] ... matched 0 nodes` advisory line, but advisory lines never block a run and nobody reads passing output, so the rule quietly never fires. | A rule Tyler believes is enforcing something has actually never matched a single node/declaration for weeks — discovered only by accident (e.g. deliberately reintroducing the violation as a smoke test). | Add a `--strict-zero-match` (or equivalent) CLI mode for `kibitzer check architecture` that promotes zero-match advisories to a non-zero exit during initial config authoring, and document it as the required first step when adding any new architecture check — closes the gap between "never fails a normal run" (intended, Story 1.1.3) and "never gets a human's attention during setup" (unintended side effect of the same design). | P2 |
| 2 | Naming rules v1's component/glob scoping (not interface-conditioned) may not express the naming conventions Tyler actually cares about — most real Go/Java naming conventions are structural ("implements Repository → ends in Repository/Client"), not path-based ("everything in this directory matches this pattern"). Gap 3 could ship, pass every test, and simply not fit the mental model it was built to serve. | Tyler writes a `naming_rules` entry expecting interface-conditioned enforcement, discovers it can only express directory-scoped patterns, and never configures another one — Phase 3's ~2-3h epic delivers zero ongoing value. | Before implementing Phase 3, check one of Tyler's real repos for an actual naming convention he'd want enforced and confirm the component-scoped shape can express it. If it can't, either cut Phase 3 for this release or add an explicit doc-comment limitation ("v1 covers physical layout conventions only, not role/interface conventions") so the gap is a communicated trade-off, not a silent disappointment. | P2 |
| 3 | Two independent, novel risks collapse into the same invisible failure: (a) Java/Kotlin's field-name-less positional AST walk (verified against only one hand-picked `to_sexp()` fixture per language) can silently misclassify or drop edges on shapes outside that fixture, and (b) `Component`/`DependencyRule` resolution glob-matches *any* string an import resolves to — including external/third-party library import paths — with no check that the match corresponds to a real, locally-declared package. Neither produces an error or an advisory; both look identical to "the code is clean." | Either kibitzer reports zero findings on a Kotlin/Java project that actually has a deliberately reintroduced violation (silent under-reporting → false confidence the architecture is clean), or it blocks a commit citing a `component-deps` violation against what turns out to be a third-party dependency import that happened to share a path segment with a locally declared component (false positive → erodes trust in the tool on day one). | (i) Require a graph edge's target to resolve to an actual repo-local node (one built from a walked file), not any arbitrary string a `Component` glob happens to match, before treating it as a dependency-rule violation — closes the external-library collision case. (ii) Extend Phase 4's grammar-verification fixtures beyond the single canonical `to_sexp()` example to cover at least one "shape variant" per language (annotated import, multi-import block) and add the malformed-source test adversarial-review.md already recommends, but assert specifically on *silent misclassification*, not just "no panic." | P1 |
| 4 | The two just-landed repair-loop fixes interact badly: a Blocking-severity check whose *only* finding is a zero-match advisory (`severity_override: Some(Advisory)`, Story 1.1.3) still makes `run_architecture_check`'s `passed = findings.is_empty()` false, which triggers the newly-generalized git-HEAD-baseline rebuild (Story 2.2.3) on *every single run* — a wasted git-archive-and-reparse cycle that then prints a nonsensical "(downgraded: this violation predates your edits)" message about a static config typo, not an actual violation. | Every batch run against a misconfigured architecture check pays a full git-snapshot rebuild and prints a confusing "predates your edits" message about something that isn't edit-introduced — surfacing as either unexplained slowness or a baffling message during the exact config-debugging moment Story 1.1.3 was designed to make friendly. | Change `passed`'s computation to exclude advisory-only findings (`passed = findings.iter().all(|f| f.severity_override.is_some())`) before deciding whether to invoke `check_native_against_git_head_repo`, and add it as an explicit acceptance criterion/test on Story 2.2.3 rather than leaving it as adversarial-review's dismissed "worth a follow-up... if it matters" minor. | P2 |
| 5 | The plan's own dogfooding phase (7) never touches a real Tyler repo — by design, since kibitzer's own source is 100% Rust — and requirements.md itself hedges that it isn't even confirmed Tyler currently uses the pre-existing, simpler `layers:` feature anywhere. Nothing in the plan requires the richer feature to actually get configured on real code, before or after merge. | The feature ships, every test and the synthetic `testdata/dogfood-architecture/` fixture pass — and months later `go-arch-lint`/`depguard` configs are still the ones actually running in Tyler's real Go projects, because nothing in the shipped plan ever required migrating one. | Add an explicit Phase 7/8 acceptance criterion requiring `component-deps` (at minimum) to be configured against one of Tyler's actual pre-existing repos currently using `go-arch-lint` or `depguard`, replacing that tool's config as the literal migration proof — not just a purpose-built fixture — before calling the feature "shipped" against requirements.md's own stated goal of replacing per-language tools. | P1 |
