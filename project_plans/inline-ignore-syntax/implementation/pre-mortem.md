# Pre-mortem: inline-ignore-syntax
**Date**: 2026-10-07

## Failure Modes

| # | Failure | First Symptom | Prevention | Severity |
|---|---------|--------------|------------|----------|
| 1 | A checker's reported `Finding.line` is not where the agent reasonably puts the comment (off-by-one, 0-based rows, multi-line anchors beyond the 6 hand-tabulated checkers). The ignore silently matches nothing, the finding persists, and the agent adds more ignores in different spots, which is the token-burn loop the feature exists to stop. `[unused-ignore]` is the only signal that an ignore matched nothing, and it is the first item in the cut order and `kibitzer run` only (never the hook). | Hook output repeats the same finding after the agent added an ignore; files accumulate 2-3 adjacent dead ignore comments; `[ignore-volume]` fires on files with only one real finding. | (a) Replace the six hand-picked anchor tests in Task 1.2.1b with a conformance test that iterates every checker in `default_checks()` against a fixture that triggers it, inserts a directive on the reported line and on the row above, and asserts the finding disappears (fail the build for any checker where it does not; document exceptions in the anchor table). (b) Make the hook, not only `kibitzer run`, tell the agent when a directive it just added matches nothing: either raise the unmatched-directive check for directives inside `changed_lines` (cheap, since the scan is already memoized) or remove Story 2.2.2 from the cut list. (c) Put the exact anchor row in the hint text ("place on line N-1 or N"), derived from the finding's own line. | P1 |
| 2 | Agents (or a hostile PR in CI) use `kibitzer:ignore` to get past blocking checks (ADR-002 makes them suppressible). The reason is only checked for non-emptiness, so `-- needed` passes. The only guardrail is `[ignore-volume]` at 5+ per file, per file only, advisory, and second in the cut order. Blocking checks lose their blocking meaning without anyone noticing. | Diff review shows ignore comments with boilerplate reasons added in the same commit as the blocking failure; ignore count grows repo-wide while `[ignore-volume]` never fires because each file has 1-4. | (a) Move `[ignore-volume]` out of the cut list and add a repo-level signal: `kibitzer run` footer prints total inline ignores and how many suppress blocking-severity findings (the count already flows through `InlineIgnoreContext`). (b) In the hook, when a directive added in `changed_lines` suppresses a blocking finding, emit a one-line advisory naming the rule and reason so the suppression is visible to the agent and in the transcript. (c) Add a minimum reason quality rule in `Reason::new` (reject single-word or a reason equal to the rule id) and test it. | P1 |
| 3 | The `inline-ignore` checker is on by default in every repo, and its unknown-rule reporting treats `KNOWN_RULES` plus the inventory registry as the whole universe. Plugin checkers (`kibitzer plugin install`), rules with built ids, or any new checker merged without a table update make a legitimate directive draw `[ignore-syntax] unknown rule`. The drift guard only reads static `"[id]"` literals, so it misses these. Agents "fix" the warning by renaming the rule to a wrong one. | Users report `unknown rule 'x' - did you mean 'y'?` on directives that work; agents rewrite correct rule ids. | Skip the unknown-rule finding unless the nearest `KNOWN_RULES`/checker name is within edit distance 2 (a typo), so unfamiliar but plausible ids stay quiet; include plugin-registered checker names in `known_rule`; add a test with a plugin-style checker name. Backtest gate (Task 4.1.1) records the unknown-rule fire count separately from `[ignore-syntax]` totals. | P2 |
| 4 | The directive-scan memo and the `source.contains("kibitzer")` fast path are specified in prose but no task defines how the memo reaches `apply_inline_ignores` (no parameter in its signature in Task 1.2.2a, no owner). The implementer either re-parses per checker (about 30 default checks per file in `kibitzer run`) or adds a global cache that grows unbounded in the daemon/LSP and returns stale directives after an edit. | `kibitzer run` slows on marker-heavy repos (the repo itself embeds markers in test strings); daemon RSS grows; a removed ignore keeps suppressing until restart. | Add an explicit task: define the memo type (owned by the per-file pass in `run_native_check`, passed by reference inside `InlineIgnoreContext` or as an argument, dropped at pass end), forbid `static`/`thread_local` in review, and add a test that a second call with changed source returns the new directives and that a pass over a marker file parses once (counter assertion). | P2 |
| 5 | The false-positive worklist stays empty or low-signal. Agents pick `ignore` over `false-positive` (no incentive, and the hint lists both), or pick `false-positive` for tradeoffs. Maintainers see no worklist, so the "regression test candidates" metric from requirements is not met. | `kibitzer check false-positives list --inline` returns "no markers found" a month after release while `kibitzer run` footers show dozens of suppressions. | In the hook footer define when to use each marker in one clause ("false-positive: the checker is wrong; ignore: the code is right for a reason") and have the `run` footer report the `false-positive`/`ignore` split. Add a weekly check in the release routine that compares the two counts, and treat a zero split as the signal to revisit the marker design. | P2 |

Resolved: Phase 0 (plan Tasks 0.1.1-0.1.3) runs the replay first as a go/no-go gate with an explicit rule (`G = R x A`: under 2% stop, 2-5% shrink, 5%+ proceed; too few samples stops). Residual: the thresholds are judgement calls and the sample is one maintainer's transcripts.
- [x] RESOLVED in plan.md: Failure #1 — Task 1.2.1b is now an all-`default_checks()` anchor conformance test with a completeness guard; Story 2.2.3 adds a hook advisory for an added directive that matches nothing inside `changed_lines` (kept as core, no longer on the cut list; justified in Design Decision 7; the `kibitzer run` variant, Story 2.2.2, is the pre-declared first cut); Story 3.1.1 hint carries the exact anchor row.
- [x] RESOLVED in plan.md and ADR-002: Failure #2 — `[ignore-volume]` removed from the cut list; `run` footer reports repo-wide total, blocking share, and `false-positive` share; Story 3.1.2 adds the `[blocking-suppressed]` hook advisory; `Reason` has a two-word, not-the-rule-id floor (Task 1.1.1d).
