# Pre-mortem: architecture-export
**Date**: 2026-08-24

## Failure Modes

| # | Failure | First Symptom | Prevention | Severity |
|---|---------|--------------|------------|----------|
| 1 | On any repo whose real code lives mostly in Phase 5 languages (Python/Java/Kotlin) or any language kibitzer never covers, `kibitzer architecture export` silently produces a "complete-looking" but near-empty `ArchModel` — unsupported-language files fail the `Language`-mapping check in Task 1.3.1b and are dropped exactly like a stray `README.md`, with no distinct counter in `PruningSummary` (which tracks `generated_files_skipped`/`private_symbols_skipped`/`files_with_parse_errors` but nothing for "no extractor exists"), so nothing in the output signals "most of this repo isn't represented." | A user/agent on a Python- or Java-heavy repo runs `architecture export`, gets a valid non-error JSON file with a handful of packages, and treats it as authoritative — the gap is discovered only when a symbol they know exists can't be found via `get_architecture_node`/`find_symbol`. | Add a `files_skipped_unsupported_language: usize` (or path list) field to `PruningSummary`, distinct from "no extension recognized at all"; have `arch_export`'s stdout summary and the MCP tools' response warn when that count is a large fraction of walked files (e.g. "62% of files in this repo aren't covered by architecture-export yet — see Phase 5"). | P1 |
| 2 | The exported-only-by-default pruning rule (Pattern Decisions table, `PruneConfig.include_private: false`) hides the majority of real code in most codebases — unexported/internal types, helpers, and private methods are the bulk of most packages — so an agent asking "where is type Y defined" or "what does this internal component do" gets `not_found`/empty results unless it already knows to pass `include_private: true`, which nothing in the default tool responses prompts it to do. | `get_architecture_node`/`list_architecture_symbols` return `not_found`/`total_matched: 0` for a symbol the caller knows exists in the source, with no signal that it exists but was pruned. | Have `get_architecture_node`'s `not_found` path distinguish "truly absent" from "exists only as a pruned private symbol" (a cheap second lookup against an unpruned view) and say so in the response; document the exported-only default prominently in both tools' `#[tool(description = ...)]` strings, not just the Pattern Decisions table. | P2 |
| 3 | Story 4.3.0's background-index state machine has two unspecified concurrency behaviors: (a) what happens when `did_save` fires while `index_state == Building` (the initial build hasn't produced a `Ready` snapshot yet — the AC only covers `did_save` while already `Ready`), and (b) nothing prevents two overlapping `did_save`-triggered rebuilds from completing out of order, letting an older (slower) rebuild's result clobber a newer one's — `rebuilding: AtomicBool` records *that* a rebuild is in flight but not *which* one is most recent. | Under rapid-fire `did_save`/`did_change` (normal during active editing, e.g. format-on-save plus manual saves), `workspace/symbol` intermittently serves index content that's older than what's on disk, or the still-indexing synthetic result flickers unpredictably, with no test covering it — this is exactly the "known-unresolved" gap flagged by the most recent adversarial review. | Before implementation: explicitly define `did_save`-during-`Building` as a no-op (the in-flight initial build already reads current on-disk state at whatever point it gets there — no second build needed), and add a monotonic `build_generation: u64` alongside `index_state` so a completing rebuild only swaps in its result if its generation is still the latest spawned; add both as acceptance criteria + a rapid-fire-save test to Story 4.3.0, not discovered post-hoc. | P2 |
| 4 | The <5s Performance Target is grounded in a wrong, unverified number — the plan states "kibitzer's own repo (~90 source files across Phase 1's Go/TS/Tsx/JS languages)"; the actual count is 29 (`find . -type f \( -name '*.go' -o -name '*.ts' -o -name '*.tsx' -o -name '*.js' \) \| wc -l` = 29, verified), and kibitzer's own repo is itself a Rust project (24 `.rs` files) — not remotely representative of the multi-language repos this feature targets. The only large-repo check (Task 1.3.1f's synthetic ~2,000-file fixture) has no hard timing assertion, just "completes, doesn't panic." | The 5s target holds in CI (it's checked against a 29-file fixture) but a real user's genuinely large monorepo takes tens of seconds to minutes on `architecture export` or the LSP's initial background index build, discovered only after users complain, since nothing regresses in CI. | Fix the file-count claim in the Performance Target section to the verified 29, and add a hard-asserted timing regression gate against a realistically-sized fixture (either the synthetic ~2,000-file fixture with an actual assertion, or a vendored real multi-language repo) instead of relying on kibitzer's own small, non-representative repo as the sole timed benchmark. | P2 |
| 5 | The C4-non-conformance disclaimer lives only in the CLI's `--help` text (Story 2.2.1's AC checks `--help` output, not the rendered diagram itself) — once a diagram is written via `--out` or piped to stdout and pasted into a PR/wiki/Slack message (the exact "shareable in a PR" use case `ux.md` names), the disclaimer doesn't travel with it, so a viewer with no CLI context can still mistake it for a standards-conformant C4 diagram. | A shared diagram (in a PR description, wiki page, or chat) gets discussed/critiqued as if it were real C4 Container/Context notation, and the confusion this feature's Pattern Decisions table explicitly tried to avoid happens anyway, downstream of the CLI where the disclaimer never reached. | Have `render_text_tree`/`render_component_diagram` emit the disclaimer inline in the artifact itself — a leading text-tree comment line plus a Mermaid `%%` comment — so it survives copy-paste into any destination, not just `--help`. | P3 |

## P1 Items (address before implementation)
- [x] #1 — **Resolved in plan.md** (2026-08-24): `PruningSummary` now has `unsupported_language_files`/`total_files_scanned` fields (Domain Glossary, Task 1.1.1c, Story 1.3.1's updated AC, Task 1.3.1b/1.3.1d); `kibitzer architecture export` prints a stdout warning when the unsupported fraction is ≥50% (new Story 2.1.1 AC, Task 2.1.1b). MCP query-tool responses were not extended with this field — they're scoped symbol lookups, not whole-model exports, so the per-run signal belongs to `export`/`diagram` (the whole-model-producing commands), not every narrow query response; the exported `arch.json`'s `pruning` field is available to any MCP tool that wants to surface it later if that judgment turns out wrong in practice.

## Also addressed opportunistically while patching for #1
- P2 #4 (wrong file-count in Performance Target section): fixed — plan.md no longer claims kibitzer's own repo as the benchmark (it's Rust, out of scope for this feature, and was never ~90 files); Task 1.3.1f now calls for a realistic external multi-language fixture instead, and the Performance Target section states the 5s figure is provisional pending that benchmark's first real run.
