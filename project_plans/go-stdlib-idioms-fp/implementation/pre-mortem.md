# Pre-mortem: go-stdlib-idioms-fp
**Date**: 2026-10-10

## Failure Modes

| # | Failure | First Symptom | Prevention | Severity |
|---|---------|--------------|------------|----------|
| 1 | `named_children()` vs `children()` indexing is wrong: commas ARE named children in this tree-sitter-go version, so the odd-index slog key logic fires at the wrong positions, suppressing message args and leaving real keys un-suppressed | AC-5 test `suppresses_slog_key_string_in_log_warn` passes because the test fixtures happen to use one key, but a user reports `"msg"` repeated 3× no longer fires in `replace-magic-literal` | Add a verification step before implementation: run `to_sexp()` on a 3-argument `argument_list` and assert comma node kinds are `","` and anonymous — fail the PR if this is unconfirmed | P1 |
| 2 | `selector_expression.utf8_text(src)` returns only the field name (`"Slice"`) rather than the full `"sort.Slice"` in some tree-sitter-go parse contexts, so the stdlib-callback allowlist never matches and AC-1 / AC-2 keep firing | Unit test `ignores_sort_slice_comparator` fails; CI is red but the fix is merged anyway under time pressure, or the test fixture uses an import alias that changes the text | validation.md Risk 4 says "confirm before landing" but gives no explicit CI gate — add a dedicated test that asserts `selector_expression` text includes the package prefix and make it mandatory | P1 |
| 3 | Blanket test-file suppression (`file_is_test && parent_is_func_literal`) silently drops real primitive-obsession findings in exported `export_test.go` helpers (which ARE test files but contain API surface), because `export_test.go` ends in `_test.go` and the guard checks only the suffix | A user with an exported helper `func Setup(host, port, user, pass string)` in `export_test.go` gets no finding; the type confusion goes undetected | Tighten the guard: suppress only when the file ends in `_test.go` AND the function's name is unexported (starts with lowercase). Alternatively, document that `export_test.go` is accepted false-negative territory with a `kibitzer:ignore` escape hatch | P2 |
| 4 | The suffix-based slog method match (`Info`, `Warn`, `Error`, `Debug`) suppresses key strings in non-logging methods that happen to share those names (e.g., an HTTP router's `.Error("path", handler)` or a metrics client's `.Warn("label", value)`), creating silent false-negatives in `replace-magic-literal` that real repeated strings never fire on | Users in projects with non-logging `Warn`/`Error` methods file a bug: "magic-literal never fires for `"path"` even though it repeats everywhere" | Tighten the suffix match to require a package-qualified prefix OR require the argument list to have ≥ 3 args (message + at least one key-value pair); add a backtest run against a corpus including an HTTP framework to confirm the false-negative rate is acceptable | P2 |
| 5 | The backtest corpus gate (AC-7) is run manually post-implementation against `kubernetes/kubernetes` only, but the initial false-positives were found in non-Kubernetes Go code; the corpus doesn't include projects that use `slices.*` heavily (Kubernetes predates the `slices` package) or `slog` heavily, so regressions in those patterns go undetected until users report them | Post-ship bug report: "`slices.SortFunc` comparator still fires on project using Go 1.21+ `slices` package" even though the unit test passes, because the backtest corpus had no `slices.*` call sites | Add at least one `slices`-heavy and one `slog`-heavy repo to the backtest corpus (e.g., `denoland/deno` uses `slog`-style logging; clone a Go 1.21+ project that uses `slices.*`) before the gate counts as passed | P2 |

## P1 Items (address before implementation)

- [ ] Failure #1 — Before writing any `collect_slog_key_ids` code, run `to_sexp()` on a real `argument_list` node and assert that comma tokens are anonymous (kind `","`, not in `named_children()`). Commit the assertion as a test or a comment with output. Gate the PR on this being verified.
- [ ] Failure #2 — Before writing the allowlist text-match, print `call_expression.child_by_field_name("function").utf8_text(src)` for `sort.Slice(...)` in a scratch binary or test, and assert the output is `"sort.Slice"` not `"Slice"`. The existing `ignores_sort_slice_comparator` unit test covers this only if it's written to fail when the text is wrong — add an explicit assertion in the test that the allowlist match fires for the exact string `"sort.Slice"`.
